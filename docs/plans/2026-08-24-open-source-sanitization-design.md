# Arkadia 开源脱敏设计

## 配置边界

任何能够直接访问第三方服务、数据库或用户账户的值都只能在运行时注入。上游订阅地址由 `UPSTREAM_SUBSCRIPTION_URL` 提供，数据库可保存管理员显式填写的覆盖值；代码、测试、文档和镜像构建上下文不提供可用默认地址。管理员名单由 `ADMIN_USERNAMES` 完成首次播种，后续仍可由现有后台维护。管理员 API 不回显环境变量中的订阅地址，避免凭据进入浏览器、截图或前端日志。

Docker 构建上下文通过 `.dockerignore` 排除 `.env`、Git 元数据、本地构建产物、测试和运维草稿。生产镜像只接收 GitHub Actions 的干净 checkout，部署时由 Compose 把环境变量传给运行容器。

## 历史与制品

公开前不仅删除当前文件，还要重写 Git 历史：彻底移除真实用户调查资料、替换历史中的订阅凭据，并把带生产主机名的提交邮箱改为 GitHub noreply 地址。重写前创建仅本机可读的 Git bundle，用于紧急恢复；远端只保留清理后的 `main`。

旧容器镜像和 Actions 构建制品可能继续保存历史源码，因此必须同步删除，不能依赖新镜像覆盖。清理后由 GitHub CI 重新执行数据库结构检查、单元测试、Next.js 构建和容器发布。生产先写入环境变量，再更新应用，确保自动同步不会因源码移除默认值而中断。

## 公开维护

仓库采用 AGPL-3.0，新增安全报告与贡献指南，示例只使用虚构域名和占位凭据。依赖更新由 Dependabot 提醒；仓库转为公开后启用 Secret Scanning、Push Protection、Dependabot alerts 和 Code Scanning。最终闸门同时检查当前快照、全部远端历史、提交元数据和可匿名获取的制品。
