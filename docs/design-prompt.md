# Arkadia UI/UX 重设计提示词

> 用法:整段复制给任何设计 AI(DeepSeek/GPT/Gemini 均可),建议附上 arkadia.work 手机端+桌面端截图。
> 拿回方案后标注要做哪几节,交回给工程侧按优先级实施。

---

# 角色
你是资深产品设计师 + 前端设计系统专家,为一个真实上线的订阅网站做 UI/UX 重设计。
你的输出将被直接交给工程师实施,必须具体到可执行,禁止空泛描述。

# 项目背景
- 产品:Arkadia(arkadia.work)——面向 LinuxDo 论坛技术社区的付费节点订阅站
- 用户画像:中国开发者,重隐私,审美偏"工具感/终端感",日常用 Clash/v2rayN 等工具,
  手机访问占比高。付费能力强但对"营销味"反感,吃"克制、专业、信息密度高"这一套
- 商业模式:注册码 100 LDC 一次性购买(库存限售)→ 送 N 天免费更新 → 之后 3 LDC/次更新额度
- 核心情绪价值:信任感(要先付钱)、新鲜感(节点每日更新,订阅名带日期)、
  安全感(不退款政策要显得专业而非霸王)

# 技术约束(不可协商)
- 组件库:@cloudflare/kumo(Cloudflare 官方,风格参考 cloudflare dashboard)
  可用组件:Button/LinkButton、Input、Badge、Banner、Switch、LayerCard(卡片)、
  Table、Toast、Tabs、Dialog、Popover、Select、Meter
- 样式:Tailwind v4 + CSS 变量做主题(现有品牌层:深墨底 #0a0d14、信号橙 #f6821f、
  网格底纹背景、Sora 展示字体 + JetBrains Mono 数字/代码双字体,深浅双主题)
- 框架 Next.js 15 App Router,响应式优先(手机 ≤768px 是主战场)
- 不能引入其他组件库或重量级动画库;CSS 动画/过渡可以

# 页面清单(需要逐页给出设计方案)
前台:
1. 首页:hero(一句话价值主张 + 实时状态:库存/最近更新日期/每批节点数/续价)、
   双定价卡(注册码 vs 更新额度)、不退款声明、页脚
2. 面板(登录后):订阅状态卡(免费期剩余/更新额度数/最近更新)、订阅链接卡
   (复制/下载/重置)、购买更新额度卡(快捷数量 1/3/5/10/30 + 自定义)、我的订单表
3. 兑换页:输码激活、支付回跳展示注册码、凭订单号找回注册码
4. 支付跳转等待页、服务条款页、错误/拒绝页
后台:
5. 总览(6 个统计卡 + 最近订单)、节点批次管理(上传/激活)、订单表(对账/取消/退款)、
   注册码库存、用户管理(封禁/加额度/重置链接)、风控(指纹簇)、设置表单

# 你要交付的内容(按此结构输出)

## 1. 设计方向定调
用 3 个关键词定义整体气质(如"控制台/仪表盘/终端感"),说明为什么适合这个用户群,
并给出 1 个能让人记住的"标志性视觉瞬间"(signature moment)

## 2. 设计令牌(直接给值)
- 色板:背景/表面/边框/文字/强调色/语义色(成功/警告/危险),十六进制值,深浅两套
- 字体:层级 scale(展示/标题/正文/辅助/等宽标注),字号行高具体值
- 间距:4/8 栅格下的间距体系;圆角;阴影(卡片悬浮/弹层)
- 动效:进入动画节奏(建议 CSS-only,给 duration/easing 具体值)

## 3. 逐页设计方案
每页给:
- 布局结构(区块从上到下,移动端单列的排列顺序)
- 关键组件用哪个 Kumo 组件 + 什么 variant
- 信息层级:第一眼看到什么,次要信息怎么收
- 具体到文案风格(按钮/空状态/错误提示的措辞调性)

## 4. UX 流程优化(重点)
- 付费转化路径:从落地到付款,哪里会流失,怎么降摩擦
- 订阅链接的分发体验:用户怎么"理解"这个链接要用在哪(客户端适配引导)
- 信任建设:不退款政策怎么呈现才专业不吓人;库存/新鲜度怎么变成卖点
- 错误与空状态:全部枚举(无库存/未激活/额度用尽/被封禁/回调未到),各给文案

## 5. 可访问性与细节
- 触控目标 ≥44px、对比度(给具体检查结论)、focus 态
- 深浅主题切换时哪些元素最容易翻车,给规避方案

# 输出要求
- 中文,Markdown,直接可执行:每个结论都落到"组件/属性/数值/文案"级别
- 改动要克制:保留现有品牌层(深墨+橙+等宽),是精修不是推翻
- 禁止输出:抽象口号("让设计更有温度")、无法落地的建议("增加动效提升体验")、
  需要换组件库/框架的方案
